# BP Space — прийом коштів

Прототип кроку «Прийом коштів» картки оренди разом із блоком «Рахунки до оплати» і правим сайдбаром розрахунків. Кілька клікабельних варіантів на однакових сценах, плюс варіант 0 — порт чинного проду як антиреференс і база вимірів.

Бриф: [BRIEF.md](BRIEF.md). Візуальна система: [DESIGN.md](DESIGN.md) (копія системного файлу CRM, не переписується).

**Публічне посилання:** https://yuliiariabchuk.github.io/bp-payment-intake-prototype/

## Запуск

```bash
npm install
npm approve-scripts esbuild
npm rebuild
npm run dev
```

Відкрити http://localhost:5173/bp-payment-intake-prototype/

Прогін: `node scripts/walk.mjs` при запущеному `npm run dev`.

## Віджет «Кадри»

Лівий нижній кут. Перемикає варіант кроку, варіант сайдбару, сцену, фізособу/юрособу і роль. Стан пишеться в URL (`?v=…&rail=…&scene=…&party=…&role=…`), тож будь-який кадр відтворюється посиланням. `Ctrl+.` ховає віджет цілком.

## База: варіант 0 (чинний прод)

Варіант 0 — порт чинного кроку «Оплата» і сайдбару за кадрами `reference/1–12` і кодом CRM (стан на 24.09). Відтворено разом із вадами: поповер-майстер, рядок, що розгортається, «крок 1 з 2» для автоматичного ПКО, п'ять і більше поверхонь «скільки ще», російські рядки в сайдбарі. Це антиреференс і база вимірів, не пропозиція.

Виміри `node scripts/walk.mjs --variants 0` на 1366×768:

| Вимір | Варіант 0 |
|---|---|
| Сцена 1, готівка на всю суму: кліків від відкритого кроку до прийнятих грошей | **5** |
| Сцена 2, оренда готівкою + застава терміналом | **10** |
| Сцена 5, окремий платіж на нарахування після оплати | **5** |
| Зміна каси в сцені 1 | **+2** кліки |
| Макс. вертикальний зсув головної дії між кліками | **161 px** |
| Макс. зсув верху кроку між кліками | **27 px** (у сцені 12 — 77 px) |
| Поверхонь, що одночасно друкують «скільки ще прийняти» | **до 8** |
| Станів одного поповера («Чим платить») | **9** у прогоні (11 у коді CRM); поповер суми — 4 |
| Горизонтальний скрол на 1366×768 | немає |
| Головна дія видна без прокрутки на старті сцени 1 | так (низ на 707 px) |
| Сцен пройдено кліками | 12 / 12 |

Поверхні «скільки ще» у варіанті 0: сума в заголовку кроку, сегмент смуги «Оренда», сегмент смуги «Застава», плейсхолдер поля суми, «Залишок за доплатами», залишок у рядку нарахування, плашка «Неповна оплата» біля «До видачі», велике число «РАСЧЁТЫ ПО АРЕНДЕ», число «Застава» в сайдбарі. Прогін рахує ті, що видно одночасно.

### Критика варіанта 0: 14/40 (Poor)

`/impeccable critique`, два незалежні агенти (дизайн-рев'ю + детектор і браузер). Повний звіт: [docs/critique-v0.md](docs/critique-v0.md).

- **P0. «Скільки ще прийняти» не має однієї відповіді.** Сцена 1: заголовок 5 100, сайдбар червоне «2 100 долг», застава 3 000. Сцена 4: 3 120 / 120 / «0 з 120». Сцена 5: 12 видимих «1 000» в одному вікні.
- **P0. Найчастіший випадок — майстер на 5 кліків, що зсувається під курсором.** Поповер перебудовується 208 → 428 px, сума — плейсхолдер, який треба підтвердити пресетом, поповер суми накриває «Прийняти».
- **P1. Ієрархія вказує не на ту дію.** «Зараз: Перейти до видачі» дублює «До видачі»; збір грошей — сірий рядок «Додати спосіб»; у керівника найяскравіше — «Пропустити оплату»; головна дія нижче 768 px у сценах 4, 5, 12.
- **P1. Мова і терміни.** ~45 російських рядків, «рахунок» у трьох значеннях, «крок 1 з 2» для автоматичного ПКО.
- **P1. Стан юрособи наступного дня нечитабельний.** Недоплату з 1С не названо, «Редагувати рахунок» на сформованому документі.

Детектор: CLI чистий (3 зауваження до шрифту 22 px); у браузері — контраст бейджа «з ПДВ» 4,4:1 і кнопки «Доповнити» 3,3:1; дизайн-рев'ю — плейсхолдер суми ≈2,4:1.

Спрощення порту (не впливають на виміри): олівець на картках відкриває редактор ціни без збереження; модалка складу рахунку і діалог «рахунок на частину суми» не відтворені; хронологія — спільна бокова панель зі сторно.

## Варіанти A–D

Чотири структури з [docs/shape.md](docs/shape.md). Візуальна мова — CRM; міняються флоу, ієрархія і кількість дій. Сайдбар поки чинний (варіант 0), його варіанти — етап 4. Усе нове відносно проду — **пропозиція**.

| | Що робить | Сцена 1 | Сцена 2 | Сцена 5 | Зсув дії | «Скільки ще» в кроці |
|---|---|---|---|---|---|---|
| **0** Чинний прод | поповер-майстер, рядок розгортається, 5 поверхонь суми | 5 | 10 | 5 | 161 px | 5 + сайдбар |
| **A** Рядок способу | таблиця лишається; спосіб і каса в рядку, **явний вибір**; «Покриває» замість «Рахунок»; список (а) + окремий блок нарахувань | 2 | 6 | 2 | 45 px | заголовок кроку |
| **B** Список до сплати | список позицій з галочками **і є складом платежу** (в); під ним один рядок прийому; журнал прийнятого | 1 | 4 | 1 | 3 px | підсумок списку |
| **C** Касове вікно | ліворуч список (б), праворуч **панель каси фіксованої висоти** з табами, пресетами і деталями способу | 1 | 4 | 1 | 0 px | заголовок панелі |
| **D** Швидкі дії | одне речення з сумою і **ряд дій**; «Розділити» для кількох платежів; переказ у боковій панелі; картки з розкриттям складу (контроль) | 1 | 3 | 1 | 0 px | речення |

Спільне для A–D: скасування тільки з хронології (сторно), рахунок на оплату — на прохання, у юрособи два (оренда з ПДВ, застава без ПДВ); скасовані нарахування видимі з причиною; ворота видачі пишуть «що далі» реченням без суми; «Пропустити оплату» бачить тільки керівник. Усі варіанти проходять 12 сцен кліками (`node scripts/walk.mjs --variants 0,A,B,C,D`).
